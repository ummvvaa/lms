## Фаза 41 — план поступления по вузу (VENTORME раздел 5)
- `roadmap.ApplicationPlan` — план по конкретной программе: несколько планов
  на ученика (по одному на программу), переключение в шапке. Дедлайн не
  копируется: живёт в раунде подачи (`plan.deadline` из `AdmissionRound`),
  сдвиг в справочнике двигает и план, и задачи (инвариант №4)
- Задачи собираются под программу (`roadmap/plans.py`): разрывы по её
  требованиям, эссе, документы, портфолио, финансы, подача в её раунд —
  только по справочнику (инвариант №10). Модель формулирует, без ключа —
  правила с пометкой. Генерация в фоне (celery), плашка прогресса
- Задачи идут через `Suggestion` (source=plan, инвариант №3) и применяются
  **самим учеником** — это его план; в журнале источник `student_proposal`.
  После применения задачи привязываются к плану (`Task.plan`), их срок
  начинает жить в дедлайне раунда. Задачи директора ученик по-прежнему не правит
- Экран `/plan`: шапка с переключателем планов, вузом, раундом, дедлайном
  и обратным отсчётом, полоса прогресса; четыре счётчика (всего, выполнено,
  в работе, осталось); вкладки «Задачи и этапы» (по категориям) и «Таймлайн»;
  удалить план (в архив с задачами)
- Кнопка «Создать план» появилась в карточке результата подбора (закрыт долг
  фазы 40). Задачи плана видны в общем роадмапе с пометкой вуза (`plan_university`)
- Директору по поступлению — сводка `/application-plans/attention/` на экране
  «Дедлайны»: сколько планов, где прогресс нулевой при близком дедлайне
