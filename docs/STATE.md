# Состояние проекта
Обновлено: 2026-08-21   Последняя фаза: 2 — Аутентификация, роли, права

## Готово
- Фаза 1: монорепо, Docker Compose на 6 сервисов, полная схема БД, админка, импорт, pytest
- Фаза 2: вход через Entra и одноразовые ссылки, роли из групп, права по доменам, каркас фронта

## Сейчас работает
- Вход: MSAL получает id_token → бэкенд проверяет JWKS/issuer/audience/срок → своя сессия в httpOnly cookie
- Вторая дверь: одноразовая ссылка на личную почту, гасится один раз; привязка второй Identity из кабинета
- Роли из групп Entra по маппингу из настроек; пересчитываются при каждом входе
- Права DRF из реестра доменов: чужой домен читается, но не пишется (403); ученик видит только себя
- Инвариант №7 на бэкенде: в ответе роли `student` полей-ярлыков нет вовсе
- Аудит: `apply_changes` плюс сигналы post_init/post_save — правки мимо API тоже в журнале
- Фронт: дизайн-токены в CSS-переменных, layout с навигацией по ролям, роутинг, TanStack Query, типы из OpenAPI
- 54 теста pytest зелёные; ruff, black, eslint, prettier чистые; `npm run build` собирается

## Следующая фаза

- Схема `suggestions` заведена в Фазе 1 (FK из AuditLog), движок применения — Фаза 5
- Проверка подписи Entra написана, но на живом тенанте не проверялась: нет реальных ENTRA_* доступов
- Импорт из XLSX написан, но проверен только на CSV — нужен файл директора
- Сигнальный аудит не знает актора (пишет `actor=None`) — правки из админки анонимны в журнале
- Экраны фронта — заглушки, наполняются с Фазы 3
