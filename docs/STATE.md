# Состояние проекта
Обновлено: 2026-08-21   Последняя фаза: 3 — Рабочие экраны

## Готово
- Фаза 1: монорепо, Docker Compose на 6 сервисов, полная схема БД, админка, импорт, pytest
- Фаза 2: вход через Entra и одноразовые ссылки, роли из групп, права по доменам, каркас фронта
- Фаза 3: CRUD и батч по доменам, табличный режим, карточка ученика, шесть дашбордов, Readiness

## Сейчас работает
- Табличный режим: колонки из реестра доменов, правка в ячейке, Tab и стрелки, вставка TSV из Excel
- Черновик копится локально, уходит одним батч-запросом; индикатор несохранённого и предупреждение при уходе
- Батч сверяет прежнее значение: чужую правку не затирает, возвращает конфликт; чужой домен отбрасывает на сервере
- Карточка ученика: пять доменов, свой редактируется, чужие с подписью «ведёт: …», вкладка истории из AuditLog
- Шесть дашбордов (5 ролей + сводный директора школы) — на 250 учениках 3–71 мс
- Readiness Score: веса из настроек, слабое звено по восстановимым баллам, ReadinessSnapshot + задача Celery
- Импорт XLSX/CSV через интерфейс: сопоставление колонок, предпросмотр, конфликты, применение с аудитом
- 81 тест pytest зелёный; ruff, black, eslint, prettier чистые; OpenAPI-схема без ошибок

## Долги и известные проблемы
- Сопоставление учеников при импорте — только точный email; матчер по ФИО с уверенностью в Фазе 5
- Сводный дашборд считает Readiness перебором в Python (71 мс на 250) — при росте школы вынести в срезы
- Проверка подписи Entra на живом тенанте не гонялась: нет реальных ENTRA_* доступов
- Сигнальный аудит пишет actor=None — правки из админки в журнале анонимны
- Схема `suggestions` заведена в Фазе 1, движок применения — Фаза 5
