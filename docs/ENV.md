# Файл настроек: что заполнять

Все настройки системы живут в одном файле — ни одного пароля, адреса или
ключа в коде нет. Файлов два, и они не связаны между собой:

| Файл | Когда используется | Лежит в git |
|---|---|---|
| `deploy/.env` | локальная работа на своём компьютере | нет |
| `deploy/.env.prod` | боевой сервер школы | нет |

Рядом лежат `deploy/.env.example` и `deploy/.env.prod.example` — это
образцы со всеми переменными и комментариями. Заполняются они так:

```bash
cp deploy/.env.example deploy/.env            # для своего компьютера
cp deploy/.env.prod.example deploy/.env.prod  # для сервера
```

Дальше открываете свой файл обычным текстовым редактором и вписываете
значения после знака `=`. Пробелы вокруг `=` не нужны, кавычки не нужны,
строка, начинающаяся с `#`, — это комментарий, система её не читает.

**После правки файла контейнеры надо перезапустить** — настройки читаются
один раз при старте:

```bash
docker compose -f deploy/docker-compose.prod.yml up -d
```

Ниже — три группы. Первую заполнять обязательно. Вторая нужна, чтобы
уходили письма (без неё нельзя пригласить людей). Третья — чтобы работала
модель (без неё система работает на правилах, это штатный режим).

## 1. Обязательные без вариантов

Без этих значений контур либо не поднимется, либо будет работать опасно.

| Переменная | Зачем нужна | Что будет, если не заполнить | Где взять значение |
|---|---|---|---|
| `DJANGO_SECRET_KEY` | Подписывает сессии и одноразовые ссылки | В бою система **не запустится**: короткий ключ роняет старт намеренно. Со стандартным ключом чужой человек может подделать вход | Сгенерировать: `openssl rand -base64 48`. Показывать никому не нужно |
| `DJANGO_DEBUG` | Режим отладки | При `1` в бою на экране ошибки видны пути к файлам и куски настроек | На сервере всегда `0`, на своём компьютере `1` |
| `DJANGO_ALLOWED_HOSTS` | Адреса, по которым система отвечает | В бою **не запустится**: пустой список означает, что сайт доступен по любому имени | Домен школы, например `lms.school.kz` |
| `CSRF_TRUSTED_ORIGINS` | С каких адресов принимаются изменения данных | Вход проходит, а любое сохранение отбивается ошибкой | Те же адреса со схемой: `https://lms.school.kz` |
| `FRONTEND_BASE_URL` | Из него собираются ссылки в письмах | Ссылка на установку пароля ведёт на `localhost` — человек по ней не попадёт | Адрес, по которому школа открывает систему: `https://lms.school.kz` |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Доступ к базе данных | Система не соединится с базой и не поднимется | Придумываете сами при первом запуске. Пароль длинный, случайный |
| `POSTGRES_HOST`, `POSTGRES_PORT` | Где искать базу | То же самое | В контуре Docker — `postgres` и `5432`, менять не нужно |
| `REDIS_URL` | Очередь фоновых задач и общий кэш | Фоновые задачи не выполняются, ограничение попыток входа считается неверно | В контуре Docker — `redis://redis:6379/0`, менять не нужно |
| `SCHOOL_NAME`, `SCHOOL_SHORT_NAME` | Название школы в интерфейсе и письмах | Везде будет написано «Beta High School» | Как называется школа. Короткое — для бокового меню |
| `VITE_SCHOOL_NAME`, `VITE_SCHOOL_SHORT_NAME` | То же название, но во фронте | Заголовок вкладки и экран входа останутся со старым названием | Те же значения, что и выше |
| `SERVER_NAME` | Домен для веб-сервера и сертификата | Сертификат выпишется не на тот домен, браузер будет ругаться | Домен школы без `https://` |
| `CERTBOT_EMAIL` | Почта для писем о продлении сертификата | Не придёт предупреждение, если сертификат перестанет продлеваться | Рабочая почта администратора |
| `TZ` | Часовой пояс: даты, дедлайны, время в журнале | Время в журнале и сроки задач будут смещены | `Asia/Almaty` |
| `SECURE_SSL_REDIRECT`, `ENABLE_HSTS` | Требовать https | Система будет доступна по незащищённому http | На сервере — `1`. Ноль только если перед системой стоит чужой прокси, который делает то же самое |

## 2. Нужные для писем

Пока не заполнено, письма **никуда не уходят**: они пишутся в журнал
сервера, а на экране «Пользователи» висит предупреждение. Пригласить
250 учеников в таком виде нельзя — ссылку каждому придётся передавать
руками (это возможно: кнопка «Показать ссылку» рядом с человеком).

| Переменная | Зачем нужна | Что будет, если не заполнить | Где взять значение |
|---|---|---|---|
| `EMAIL_HOST` | Адрес почтового сервера, через который уходят письма | Письма не отправляются вообще | В личном кабинете сервиса рассылок, раздел SMTP. Например `smtp.sendgrid.net` |
| `EMAIL_PORT` | Порт того же сервера | Письма не отправляются | Обычно `587` |
| `EMAIL_HOST_USER` | Имя пользователя для входа на почтовый сервер | Сервер отклонит письма | Там же, где адрес сервера |
| `EMAIL_HOST_PASSWORD` | Ключ или пароль для того же входа | Сервер отклонит письма | Создаётся в кабинете сервиса. Это не пароль от вашей почты |
| `EMAIL_USE_TLS` | Шифровать соединение с почтовым сервером | Письма уйдут открытым текстом или не уйдут вовсе | `1` для порта 587 |
| `EMAIL_USE_SSL` | То же, но для порта 465 | — | `0`, если порт 587 |
| `DEFAULT_FROM_EMAIL` | Адрес, с которого приходят письма школы | Письма уйдут с адреса-заглушки и попадут в спам | Адрес на домене школы, подтверждённый в сервисе рассылок |

**Важно.** Не берите логин и пароль от почтового ящика Microsoft.
Такой способ Microsoft отключает, и в один день письма перестанут
уходить без предупреждения. Нужен сервис рассылок — любой, лишь бы
у него был SMTP.

**Как проверить, что работает:**

```bash
docker compose -f deploy/docker-compose.prod.yml exec backend \
  python manage.py check_mail --to вы@школа.kz
```

Если письмо не пришло — раздел «Почта» в `docs/DEPLOY.md`, там разобраны
все причины по порядку.

## 3. Нужные для модели

Без ключа система работает **на правилах**: разборы и подсказки проще
формулировками, но всё на месте. Это штатный режим, а не поломка.

| Переменная | Зачем нужна | Что будет, если не заполнить | Где взять значение |
|---|---|---|---|
| `LLM_API_KEY` | Ключ доступа к модели | Помощник и разборы работают на правилах, свободные вопросы честно отвечают, что модель не подключена | В личном кабинете Anthropic, раздел API Keys |
| `LLM_MODEL` | Какая именно модель отвечает | Возьмётся значение по умолчанию | Оставьте как в примере, если нет причины менять |
| `LLM_MONTHLY_LIMIT` | Потолок расходов в долларах за месяц | `0` — потолка нет, и счёт ничем не ограничен | Сумма, которую школа готова тратить в месяц. Например `50` |
| `LLM_PRICE_INPUT`, `LLM_PRICE_OUTPUT`, `LLM_PRICE_SEARCH` | По ним считается стоимость на экране «Расходы на ИИ» | Расходы посчитаются по старым ценам | Прайс-лист провайдера |
| `LLM_SEARCH` | Разрешить модели искать по официальным сайтам вузов | `0` — модель не ходит в интернет и работает только по справочнику | `1`. Форумы и агрегаторы недоступны в любом случае |
| `LLM_RATE` | Сколько обращений к модели в минуту разрешено | Ошибка в чужом скрипте может съесть месячный бюджет за час | `20/min` |
| `LLM_TIMEOUT`, `LLM_RETRIES` | Сколько ждать ответа и сколько раз повторить при сбое | Возьмутся значения по умолчанию | Менять не нужно |

**Как проверить, что работает:**

```bash
docker compose -f deploy/docker-compose.prod.yml exec backend \
  python manage.py check_llm
```

Команда пройдёт все операции подряд и по каждой напишет, ответила модель
или правила.

## 3а. Блокировка входа

Заполнять не обязательно, но школьный адрес стоит вписать в первый же день.

| Переменная | Зачем нужна | Что будет, если не заполнить | Где взять значение |
|---|---|---|---|
| `LOGIN_TRUSTED_NETWORKS` | Адреса и подсети, для которых блокировка по адресу не действует — по учётной записи они блокируются как все | Один ученик, потыкавший пароль наугад сто раз за час, запрёт вход всей школе за тем же адресом на время | Внешний адрес школьного интернета: его видно на экране «Пользователи» → «Блокировки входа» в строке заблокированного адреса, или спросить у провайдера. Несколько — через запятую: `10.0.0.5,192.168.1.0/24` |
| `LOGIN_IP_FAILURES` | Сколько неудач за час с одного адреса до блокировки | Порог 100 — рассчитан на 250 человек за одним адресом | Менять не нужно; порог по учётной записи (5) в настройках нет и не смягчается |

## 3б. Портфолио ученика

Заполнять не нужно: рабочие значения стоят по умолчанию.

| Переменная | Зачем нужна | Что будет, если не заполнить | Где взять значение |
|---|---|---|---|
| `PORTFOLIO_W_PROFILE` … `PORTFOLIO_W_DOCUMENTS` | Веса шести разделов процента заполнения портфолио (профиль, баллы, достижения, олимпиады, спорт, документы), в сумме 100. Это «сколько ученик о себе рассказал», а не готовность к подаче | Действуют значения по умолчанию: 20 / 25 / 20 / 10 / 10 / 15 | Менять, только если школа решила считать заполненность иначе |

## 4. Только для контура разработки

На сервере эти переменные не нужны и должны оставаться пустыми.

| Переменная | Зачем нужна | Что будет, если не заполнить | Где взять значение |
|---|---|---|---|
| `DEV_STUDENT_PASSWORD` … `DEV_ADMIN_PASSWORD` | Пароли разработческих записей `*@dev.local` для команды `create_dev_users` | Команда откажется работать и назовёт пустые переменные | Придумать самим. В бою команда не работает вовсе |
| `PROBE_PASSWORD` | Пароль семи одноразовых записей `*@probe.local`, под которыми идёт браузерный прогон (`create_probe_users` перед прогоном, `purge_probe_users` после) | Прогон не запустится: команда назовёт переменную. На сервере не нужна — в бою такие записи не заводятся и не входят | Придумать самим, не короче 10 знаков. Живёт в `e2e/.env` |

## Готовый кусок для вставки

Скопируйте целиком в свой `deploy/.env.prod` и заполните пустые места.
Всё, чего здесь нет, брать из `deploy/.env.prod.example` — там перечислены
остальные переменные с рабочими значениями.

```env
# ---------- обязательное ----------
DJANGO_SETTINGS_MODULE=config.settings.prod
# сгенерировать: openssl rand -base64 48
DJANGO_SECRET_KEY=
DJANGO_DEBUG=0
# домен школы без https://
DJANGO_ALLOWED_HOSTS=
SERVER_NAME=
# тот же домен, но со схемой
CSRF_TRUSTED_ORIGINS=https://
FRONTEND_BASE_URL=https://
TZ=Asia/Almaty

# база данных: пароль придумайте длинный и случайный
POSTGRES_DB=lms
POSTGRES_USER=lms
POSTGRES_PASSWORD=
POSTGRES_HOST=postgres
POSTGRES_PORT=5432
REDIS_URL=redis://redis:6379/0

# название школы: и для сервера, и для фронта
SCHOOL_NAME=
SCHOOL_SHORT_NAME=
VITE_SCHOOL_NAME=
VITE_SCHOOL_SHORT_NAME=

# https обязателен, оба значения — единицы
SECURE_SSL_REDIRECT=1
ENABLE_HSTS=1
# почта для писем о продлении сертификата
CERTBOT_EMAIL=

# ---------- письма ----------
# пока EMAIL_HOST пуст, письма никуда не уходят
EMAIL_HOST=
EMAIL_PORT=587
EMAIL_HOST_USER=
EMAIL_HOST_PASSWORD=
EMAIL_USE_TLS=1
EMAIL_USE_SSL=0
# адрес на домене школы, подтверждённый в сервисе рассылок
DEFAULT_FROM_EMAIL=

# ---------- модель ----------
# пусто — система работает на правилах, это нормально
LLM_API_KEY=
LLM_PROVIDER=anthropic
LLM_MODEL=claude-sonnet-5
# потолок расходов в долларах за месяц, 0 — без потолка
LLM_MONTHLY_LIMIT=0
LLM_SEARCH=1
LLM_RATE=20/min
```

## Чего в файле быть не должно

- **Паролей людей.** Их система не хранит и не задаёт: человек
  придумывает пароль сам по ссылке из письма.
- **Ключей в git.** Файлы `.env` и `.env.prod` в репозиторий не попадают —
  это проверяется тестом. Если ключ всё-таки попал в git, его надо
  считать раскрытым и выпустить заново.
- **Значений «на всякий случай».** Пустая строка и отсутствие строки —
  разные вещи: пустая строка означает «пусто», а отсутствие — «взять
  значение по умолчанию». Если не уверены, уберите строку целиком.

## Если что-то пошло не так

| Что видно | В чём обычно дело |
|---|---|
| Контейнер `backend` не стартует, в журнале «DJANGO_SECRET_KEY» | Ключ короче 32 символов или не задан |
| Контейнер `backend` не стартует, в журнале «ALLOWED_HOSTS» | Не задан домен школы |
| Вход проходит, но любое сохранение даёт ошибку | Не задан или задан не тот `CSRF_TRUSTED_ORIGINS` |
| Ссылка из письма ведёт на `localhost` | Не задан `FRONTEND_BASE_URL` |
| На экране «Пользователи» плашка «Письма не уходят» | Не заполнена группа 2 |
| Помощник отвечает «модель не подключена» | Не заполнен `LLM_API_KEY` — это допустимый режим работы |
| Помощник перестал отвечать в середине месяца | Выбран `LLM_MONTHLY_LIMIT`. Экран «Расходы на ИИ» покажет, на что ушло |
