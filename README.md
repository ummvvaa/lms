# BHS LMS

Внутренняя система частной школы для сопровождения выпускников на пути
к зарубежным вузам и Назарбаев Университету. Всё, что школа знает
об ученике — баллы экзаменов, документы, список вузов, посещаемость,
контакты родителей — в одной карточке, и у каждой роли ровно те права,
которые нужны для её работы.

## Роли и домены

Каждое поле данных принадлежит одному домену, у домена один владелец.
Права, валидация и колонки интерфейса строятся из одного реестра —
`backend/core/domains.py`.

| Домен | Владелец | Содержимое |
|---|---|---|
| `behavior` | директор школы | посещаемость, замечания, контакты родителей |
| `admission` | директор по поступлению | контакты, ссылки, GPA, вузы |
| `documents` | директор по поступлению | паспорт, транскрипт, сертификаты, рекомендации |
| `exam` | академический директор | баллы IELTS и SAT, цели, пробные экзамены |
| `talent` | директор по талантам | олимпиады, достижения, портфолио |
| `sport` | директор по спорту | вид спорта, разряд, соревнования |

- **Ученик** вносит данные о себе и видит только своё. Внутренние метки
  и заметки сотрудников ему не показываются ни в интерфейсе, ни в API.
- **Директор** редактирует свой домен, остальные видит на чтение,
  подтверждает предложения учеников по своим полям.
- **Куратор** ведёт свои группы: подтверждает экзамены и документы,
  вносит посещаемость и контакты, читает карточку целиком. Ученики
  других групп для него не существуют.
- **Администратор** видит и редактирует всё; каждая правка помечается
  в журнале.

## Принципы

- Данные вносит ученик, подтверждает сотрудник. Исключение — то, что
  знает школа, а не ученик: посещаемость, замечания, контакты.
- Всё, что имеет историю, хранится строками с датами, а не полями.
- Каждое изменение доменного поля пишется в журнал с автором и источником.
- Удаление — мягкое: запись уходит в архив, журнал сохраняет след автора.
- Соответствие требованиям вуза считается механически от порогов
  в справочнике и никогда не называется «шансом» или «прогнозом».

## Стек

**Backend:** Python 3.12, Django 5.2, Django REST Framework, PostgreSQL 16,
Celery + Redis.

**Frontend:** React 19, TypeScript, Vite, TanStack Query, Tailwind 4,
shadcn/ui.

**Инфраструктура:** Docker Compose, Caddy.

**Тесты:** pytest, Playwright, прогон API под каждой ролью.

## Запуск

```bash
git clone <repo> lms && cd lms
cp deploy/.env.example deploy/.env
docker compose up
```

Фронт — http://localhost:5173, API — http://localhost:8000/api/.

База стартует пустой. Первая учётная запись создаётся из терминала,
пароль человек задаёт сам по ссылке:

```bash
docker compose exec backend python manage.py invite_user --email you@school.kz --role admin
```

Пароли учеников от внешних сервисов хранятся зашифрованными; ключ —
переменная `CREDENTIALS_KEY`, без неё боевой контур не стартует.

## Проверки

```bash
docker compose exec backend pytest
docker compose exec backend ruff check . && docker compose exec backend black --check .
docker compose exec frontend npm run typecheck && docker compose exec frontend npm run lint
cd e2e && npm test
cd e2e && python3 api_probe.py
```
