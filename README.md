# BHS LMS — платформа подготовки к поступлению

Внутренняя система частной школы для сопровождения выпускников
на пути к зарубежным вузам и Назарбаев Университету. Собирает в одной
карточке всё, что школа знает об ученике: баллы экзаменов, документы,
список вузов, посещаемость, контакты родителей — и даёт каждой роли
ровно те права, которые нужны для её работы.

## Роли и домены

Каждое поле данных принадлежит ровно одному домену, у домена один
владелец. Права, валидация и колонки интерфейса строятся из одного
реестра — `backend/core/domains.py`.

| Домен | Владелец | Содержимое |
|---|---|---|
| `behavior` | директор школы | посещаемость, замечания, контакты родителей |
| `admission` | директор по поступлению | контакты, пароли сервисов, ссылки, GPA, вузы |
| `documents` | директор по поступлению | паспорт, транскрипт, сертификаты, рекомендации |
| `exam` | академический директор | баллы IELTS и SAT, цели, пробные экзамены |
| `talent` | директор по талантам | олимпиады, достижения, портфолио |
| `sport` | директор по спорту | вид спорта, разряд, соревнования |

**Ученик** вносит данные о себе и видит только своё. Внутренние метки,
заметки кураторов и групповая статистика ему не показываются ни в
интерфейсе, ни в ответах API.

**Директор** редактирует свой домен, остальные видит на чтение,
подтверждает предложения учеников по своим полям.

**Куратор** ведёт 2–3 группы: подтверждает экзамены и документы,
вносит посещаемость, замечания и контакты родителей, читает карточку
целиком. Ученики других групп для него не существуют — сервер
отвечает 404, а не 403.

**Администратор** видит и редактирует все домены; каждая правка
помечается в журнале.

Учителям учётные записи не требуются: результаты пробных экзаменов
загружаются файлом.

## Основные принципы

- Данные вносит ученик, подтверждает сотрудник школы. Исключение —
  то, что знает школа, а не ученик: посещаемость, замечания, контакты.
- Всё, что имеет историю, хранится строками с датами, а не полями.
- Изменение любого доменного поля пишется в журнал с источником
  (ручной ввод, импорт, синхронизация) и автором.
- Удаление данных с историей — мягкое: запись уходит в архив, журнал
  сохраняет след автора. Физическое удаление — только через
  предпросмотр последствий и явное подтверждение.
- Соответствие требованиям вуза считается механически от порогов
  в справочнике и никогда не называется «шансом» или «прогнозом».

## Стек

**Backend:** Python 3.12, Django 5.2, Django REST Framework,
PostgreSQL 16, Celery + Redis, `cryptography` (Fernet) для секретов
учеников.

**Frontend:** React 19, TypeScript, Vite, TanStack Query,
react-router 6, Tailwind 4, shadcn/ui.

**Инфраструктура:** Docker Compose, Caddy (TLS), rclone для бэкапов.

**Тесты:** pytest, Playwright, собственный прогон API под каждой ролью.

## Запуск

```bash
git clone <repo> lms && cd lms
cp deploy/.env.example deploy/.env    # пароли БД, ключ шифрования
docker compose up
```

Корневой `docker-compose.yml` подключает `deploy/docker-compose.yml`.
Миграции применяются при старте бэкенда; данных они не заводят — только
служебные справочники. База стартует без единого ученика.

- Фронт: http://localhost:5173
- API: http://localhost:8000/api/
- OpenAPI: http://localhost:8000/api/docs/

### Ключ шифрования

Пароли учеников от внешних сервисов хранятся зашифрованными.
`CREDENTIALS_KEY` обязателен — без него боевой контур не стартует.

```bash
docker compose exec backend python -c \
  "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
docker compose exec backend python manage.py credentials_key --init
```

Ключ хранится вне репозитория. Потеря ключа означает потерю всех
зашифрованных данных без возможности восстановления.

### Первые данные

```bash
# справочник вузов
docker compose exec backend python manage.py seed_universities

# первая учётная запись — придёт ссылка на установку пароля
docker compose exec backend python manage.py invite_user \
  --email you@school.kz --role admin

# ученики списком из файла; повторный запуск не создаёт дублей
docker compose exec backend python manage.py enroll_students --file <файл>
```

Пароли пользователи задают сами по ссылке; временная ссылка действует
48 часов. Никто в школе не видит чужих паролей.

Для разработки записи всех ролей заводит `create_dev_users`
(только при `DEBUG=1`, пароли из `deploy/.env`).

### Проверка готовности

```bash
docker compose exec backend python manage.py preflight
```

Печатает список проверок «ок / не ок», ничего не меняя: боевые
настройки, доверенные сети, почта, бэкапы, ключ шифрования, отсутствие
тестовых записей, куратор у каждой группы, миграции.

Тестовые ученики помечаются явно и удаляются одной командой:

```bash
docker compose exec backend python manage.py mark_fictional --emails <список>
docker compose exec backend python manage.py purge_fictional --dry-run
```

## Импорт данных

Один мастер импорта на все домены: файл → что заполняем → проверка
строк → применить.

- Соответствия «колонка → поле → домен» описаны реестром
  `backend/students/import_registry.py`. Мастер, проверка и отчёт
  читают его; новая колонка — одна строка в реестре.
- На втором шаге видно каждую распознанную колонку, её поле, домен
  и владельца. Домены выбираются; невыбранное не записывается
  и попадает в отчёт.
- Администратор заполняет любые домены, владелец — свои.
- Загрузка применяется одной транзакцией; повторный импорт обновляет,
  а не дублирует.
- Строки с ошибками (ученик не найден, значение вне шкалы, дубль)
  исправляются или пропускаются до применения.

Результаты пробных экзаменов загружаются отдельным мастером
(`Пробники → Загрузить`) и не смешиваются с официальными баллами.

## Проверки

```bash
docker compose exec backend pytest
docker compose exec backend ruff check .
docker compose exec backend black --check .
docker compose exec backend python manage.py makemigrations --check
docker compose exec frontend npm run typecheck
docker compose exec frontend npm run lint
docker compose exec frontend npm run build

cp e2e/.env.example e2e/.env && cd e2e && npm install
npm test                    # браузерные сценарии
python3 api_probe.py        # прогон API под всеми ролями
```

Браузерные сценарии работают под одноразовыми учётными записями
`*@probe.local`: `e2e/run.sh` создаёт их перед прогоном и удаляет
после, включая прерванный прогон. Полный прогон занимает около
полутора часов; на время прогона контейнеры не трогать.

### Эталоны раскладки

Визуальное сравнение живёт в проекте `baseline` и сверяется
со снимками в `e2e/shots/baseline/` на двух ширинах — 1440 и 390.
Снимки в репозиторий не входят: они зависят от сглаживания шрифтов
конкретной машины. В свежем клоне их нужно записать:

```bash
cd e2e
npm test -- --project=baseline-seed --project=baseline --update-snapshots
```

Снимки делаются на фиксированном посеве (`baseline-seed`), который
обнуляет базу и заводит данные, закреплённые в коде. Порог расхождения —
2%; зависящие от даты элементы маскируются.

## Структура

```
backend/
  config/         настройки по окружениям
  core/           реестр доменов, права, скоупинг, аудит, точки входа
  accounts/       роли, кураторские назначения, выдача паролей
  students/       карточка ученика, документы, секреты, импорт, дисциплина
  universities/   справочник вузов, требования, подбор, стипендии
  suggestions/    очередь подтверждений
  prep/           подготовка к экзаменам, пробники, банк заданий
  roadmap/        задачи и календарь ученика
  engagement/     посещаемость, обзвон, уведомления
  directories/    справочники
  materials/      учебные материалы
frontend/         React-приложение
e2e/              Playwright, прогон API, посев данных
deploy/           compose-файлы, Caddy, бэкапы, deploy.sh
```
