# Платформа подготовки к поступлению — рабочие правила

Внутренняя платформа частной школы. Пять директоров ведут свои домены,
ученик видит свой кабинет. Данные заводятся импортом и руками, база стартует пустой.

## Стек

Python 3.12, Django 5 + DRF, PostgreSQL 16, Celery + Redis.
React 19 + TypeScript + Vite, TanStack Query, TanStack Table, react-router.
Интерфейс — Tailwind 4 и компоненты shadcn/ui (стиль `base-nova`, под ним Base UI)
в `frontend/src/components/ui`, движение — `motion`. Компоненты добираются через
MCP-сервер shadcn, а не пишутся по памяти.
Разворачивается на своём VPS через Docker Compose.

## Структура монорепо

```
/backend        Django-проект, приложения по доменам
  config/       настройки по окружениям, urls, celery
  core/         реестр владения полями (domains.py), AuditLog
  accounts/     User, Identity, Role
  students/     StudyGroup, Student, пять профилей, дочерние таблицы истории
  universities/ University, Program, AdmissionRound, StudentUniversity
/frontend       React + Vite
/docs           STATE.md, DEFECTS.md и прочая документация
/e2e            браузерные проверки Playwright и прогон API по ролям
/deploy         docker-compose, nginx, .env.example
CLAUDE.md
prototype.html  кликабельный прототип — референс интерфейса
```

`docker compose up` из корня поднимает весь контур (корневой compose делает
`include` на `deploy/docker-compose.yml`).

## Конвенции

- Комментарии и docstring — по-русски, имена сущностей и полей — по-английски.
- Тесты — pytest, покрываем инварианты, а не проценты покрытия.
- Одна осмысленная миграция на фазу.
- Секреты только через переменные окружения, `deploy/.env.example` держим актуальным.
- Линтеры: `ruff` + `black` на бэке, `eslint` + `prettier` на фронте.
- Статусы и ярлыки — `TextChoices`, значения на английском, человеческие подписи на русском.
- **Фаза не закрыта, пока интерфейс не проверен кликами в живом браузере.** Кнопка считается
  рабочей только если по клику ушёл сетевой запрос, ответ пришёл 2xx без ошибок в консоли и
  в логах бэкенда, а изменение видно в базе после перезагрузки. Пустой обработчик, заглушка
  и ссылка в никуда — дефекты. Параллельно API прогоняется под каждой ролью: браузер и сырой
  JSON ловят разные баги.

## Инварианты — нарушать нельзя

1. **У каждого поля ровно один владелец-домен.** Пять доменов: `behavior` (Салтанат),
   `admission` (Асем), `exam` (Кымбат), `talent` (Арман), `sport` (Нурлыбек).
   Директор редактирует только свой домен, чужие поля видит, но не меняет.
2. **Реестр владения — один файл** (`backend/core/domains.py`). Из него питаются права DRF,
   валидатор предложений и генерация колонок на фронте. Нигде не дублировать.
3. **ИИ никогда не пишет в основные таблицы.** Только создаёт `Suggestion`. Применяет человек.
4. **Дедлайн принадлежит вузу, а не ученику.** Живёт в `AdmissionRound`. Меняется один раз —
   пересчитывается у всех.
5. **То, что имеет историю, хранится строками, а не полями.** Моки, соревнования,
   активности — дочерние таблицы с датами.
6. **Никакого JSONB для доменных данных.** Типизированные колонки: по ним строятся все дашборды.
7. **Ученику не показываются внутренние ярлыки** `critical`, `needs_supervision`, `A/B/C`,
   `strong/medium/weak`. Ни в API-ответах для роли «ученик», ни в интерфейсе.
   У ученика — задачи и процент готовности.
8. **База стартует пустой.** Никаких фикстур с выдуманными учениками.
9. **Всякое изменение доменного поля пишется в `AuditLog`** с указанием источника:
   `manual | import | ai | sync`.

10. **ИИ не выдумывает вузы, программы и требования.** Подбор и объяснения строятся только на
    записях справочника. Если данных нет — так и говорит, а не достраивает по памяти. Название
    вуза, которого нет в `University`, в ответе появиться не может.
11. **Процент соответствия — это не шанс поступления.** Считается механически от порогов в
    `AdmissionRequirement`. В интерфейсе называется «соответствие требованиям», нигде не
    называется «шансом», «вероятностью» или «прогнозом». Обещать ребёнку вероятность
    поступления мы не имеем права.
12. **Геймификация награждает действия, а не результаты.** XP даётся за выполненные задачи,
    решённые упражнения, заполненные разделы. За балл IELTS или GPA XP не начисляется
    никогда — иначе система начнёт поощрять приписки.
13. **Удаление данных с историей — мягкое.** Ученики, профили, попытки экзаменов, активности,
    соревнования, пользователи не удаляются физически. Помечаются архивными и исчезают
    из интерфейса, но остаются в базе и в аудите — иначе журнал изменений начнёт ссылаться
    в пустоту. Физически удалять можно только справочники и записи без истории: вузы,
    программы, требования, раунды, шаблоны задач, вопросы банка заданий.
14. **Непроверенные данные помечаются явно.** Запись справочника, попавшая туда не от
    сотрудника школы и не с официального сайта, имеет признак «не подтверждено» и видимую
    плашку в интерфейсе. Ученику она показывается только с этой плашкой, и процент
    соответствия по ней сопровождается той же оговоркой.

## Решения

2026-08-21 — реестр доменов как единственный источник владения полями — права DRF, валидатор предложений и колонки фронта не должны расходиться
2026-08-21 — профили один-к-одному со Student вместо широкой таблицы — у каждого домена своя таблица, права проверяются на уровне модели
2026-08-21 — идентичности вынесены в отдельную таблицу Identity — выпускник входит по личной почте после отключения школьного Entra
2026-08-21 — AuditLog хранит значения строками — универсально для любых типов полей, читаемо в интерфейсе истории
2026-08-21 — корневой docker-compose.yml делает include на deploy/ — `docker compose up` работает из корня, файлы контура лежат в /deploy
2026-08-21 — своя сессия в httpOnly cookie вместо проброса токена Microsoft — токен провайдера не хранится на фронте и не ходит в каждом запросе
2026-08-21 — маппинг групп Entra на роли через переменную окружения — состав групп меняется без выката кода
2026-08-21 — фильтрация полей в `get_fields()`, а не в `__init__` — во вложенном сериализаторе контекст запроса появляется только к моменту отдачи
2026-08-21 — аудит подстрахован сигналами post_init/post_save — правки из админки и shell идут мимо `apply_changes`
2026-08-21 — одноразовая ссылка хранится хешем и отвечает одинаково на известную и неизвестную почту — форма не должна работать как проверка «есть ли такой человек»
2026-08-21 — веса Readiness в настройках, вес отсутствующего домена делится между остальными — у неспортсмена потолок готовности должен оставаться 100%
2026-08-21 — слабое звено по восстановимым баллам `(100−v)×вес`, а не по минимальному проценту — вкладываться надо туда, где вернётся больше итога
2026-08-21 — батч принимает `expected` и сверяет прежнее значение — двое директоров в одной таблице не затирают правки друг друга
2026-08-21 — колонки таблицы строятся из `/api/meta/domains/` — реестр остаётся единственным источником, фронт не дублирует состав полей
2026-08-21 — дашборды считаются агрегатами в БД, а не перебором учеников — критерий «меньше секунды на 250» держится с запасом
2026-08-21 — IELTS/TOEFL и SAT/ACT — группы альтернатив, достаточно одного — иначе ученик с IELTS 7.0 вечно «не хватает данных по TOEFL» и ни одна программа не открывается
2026-08-21 — разрыв округляется вверх до шага экзамена — добрать 0.1 IELTS нельзя, шкала ходит по 0.5
2026-08-21 — соответствие вычисляемое, не хранимое — профиль меняется каждый день, копия вердикта устаревала бы молча
2026-08-21 — задача из дедлайна ссылается на AdmissionRound, а не копирует дату — сдвиг дедлайна двигает задачи у всех (инвариант №4)
2026-08-21 — пустой порог в требованиях значит «требования нет», а не ноль — иначе все проходили бы по незаполненным колонкам
2026-08-21 — валидатор чужого домена в коде, а не в промпте — модель может ошибиться, промпт можно обойти, фильтр в коде обойти нельзя
2026-08-21 — матчер имён не выбирает молча при неоднозначности — это главный источник тихих ошибок: балл уезжает не тому ученику и никто не замечает
2026-08-21 — применение сверяет прежнее значение, откат — текущее — иначе предложение затирает правку, сделанную после его создания
2026-08-21 — система работает без ключа модели: разбор правилами, объяснения из движка соответствия — школа не должна вставать из-за недоступного провайдера
2026-08-21 — pytest запускается с явным --ds=config.settings.test — в контейнере DJANGO_SETTINGS_MODULE=dev перебивал ini-настройку, и тесты шли на настройках разработки
2026-08-21 — профиль выпускника на момент поступления хранится копией — правка карточки ученика не должна переписывать историю, по которой сверяются нынешние
2026-08-21 — запрос на менторство невидим выпускнику до одобрения сотрудником — выпускник не служба поддержки, школа отвечает за то, кого к нему направляют
2026-08-21 — сверка ходит только по домену вуза из справочника и Common App — на форумах числа живут своей жизнью, а ошибка в дедлайне стоит года
2026-08-21 — бэкап сразу проверяется восстановлением во временную базу — непроверенный бэкап это не бэкап, а надежда
2026-08-21 — nginx резолвит апстрим через переменную и resolver — иначе после каждого пересоздания бэкенда отдаёт 502 по старому IP
2026-08-22 — проверка каждой фазы живым браузером (Playwright в `/e2e`) плюс прогон API по ролям — инвариант №7 один раз уже ломался именно в ответе API, а в интерфейсе выглядел рабочим
2026-08-22 — демо-данные заводятся управляемой командой `seed_demo` под DEBUG, а не фикстурами — инвариант №8 запрещает выдуманных учеников в боевой базе, но без данных нечего проверять
2026-08-22 — `CSRF_TRUSTED_ORIGINS` читается в base, а не только в prod — фронт живёт на своём порту, Origin и Host не совпадают, и после входа отбивалась каждая запись
2026-08-22 — размер страницы задаётся запросом с потолком 500 — без `page_size_query_param` DRF молча отдаёт первые 50, и директор не видит остальных учеников
2026-08-22 — значение, не подходящее колонке, отклоняет строку с человеческим текстом (`core.audit.coerce`) — глотать ValidationError и падать на save нельзя, директор должен понять, что он набрал не так
2026-08-22 — список учеников отдаёт профили пяти доменов — иначе таблица рисует пустые ячейки и сохраняет с пустым `expected`, превращая каждую правку в конфликт
2026-08-22 — порядок списка учеников включает `id` — в школе есть тёзки, без уникального ключа строки перескакивают между страницами
2026-08-22 — актор для сигнального аудита живёт в контекстной переменной запроса — правка из админки шла мимо `apply_changes` и оставалась в журнале анонимной
2026-08-22 — разделы навигации директора — якоря секций его дашборда, а не отдельные экраны — пункт меню, ведущий на тот же экран, обманывает
2026-08-22 — реестр команд помощника содержит только построенное, остальное лежит в `NOT_BUILT_YET` — кнопка без обработчика хуже отсутствующей кнопки
2026-08-22 — вход по почте и паролю, Microsoft убран полностью — школа не хочет зависеть от внешнего провайдера; модель `Identity` осталась, чтобы вернуть внешний вход позже без переделки аутентификации (отменяет решения от 2026-08-21 про Entra и маппинг групп)
2026-08-22 — блокировка перебора считается по журналу `LoginAttempt` в базе, а не по счётчику в кэше — после перезапуска контейнера перебор не должен начинаться с чистого листа
2026-08-22 — порог блокировки для адреса выше, чем для учётной записи (15 против 5) — за одним школьным IP сидит вся школа, и один забывчивый не должен запирать дверь остальным
2026-08-22 — попытки входа пишутся в отдельную таблицу, а не в `AuditLog` — тот ведёт доменные поля учеников, и события аутентификации засорили бы историю карточки
2026-08-22 — обязательная смена пароля проверяется middleware на сервере, а не только экраном — иначе «обязательная» смена обходится одним запросом к API
2026-08-22 — вместо второй роли `admin` у Салтанат — флаг «видит всю школу»: читает все домены и сводный вид, пишет только свой; роль остаётся одна, инвариант №1 не размывается
2026-08-22 — администратор не задаёт пароль пользователю: заводит запись и шлёт ссылку — пароль не должен быть известен никому, кроме владельца
2026-08-22 — пользователи отключаются, а не удаляются — на них висят записи `AuditLog`, и удаление развалило бы историю правок
2026-08-22 — общий кэш в Redis вместо LocMemCache — у локального кэша он свой на каждый воркер gunicorn, и ограничение частоты запросов почти не считалось
2026-08-22 — исчезнувшая сессия отвечает 401, а не 500 (`core.sessions`) — вышел во второй вкладке, первая должна спокойно уйти на вход, а не показать трассировку
2026-08-22 — процент соответствия считается от нижней планки шкалы, а не от нуля — IELTS 6.0 при пороге 6.5 это 67%, а не 92%: шкала экзамена начинается не с нуля, и число не должно льстить
2026-08-22 — веса позиций соответствия в настройках рядом с весами Readiness — формула конфигурируема, школа меняет её без выката
2026-08-22 — группа альтернатив весит как одна позиция — иначе ученик с IELTS, но без TOEFL терял бы половину «английского» веса ни за что
2026-08-22 — процент всегда идёт с разбивкой по позициям и словесным разрывом — число без объяснения бесполезно и вводит в заблуждение
2026-08-22 — подбор отдаёт модели список программ и принимает только их id — инвариант №10 держится кодом, а не промптом: выдумать вуз физически нечем
2026-08-22 — список стран и русских названий специальностей в коде подбора — это словарь слов, а не вузов: без него нельзя отличить «такой страны нет в справочнике» от «страна в запросе не названа»
2026-08-22 — запись, добавленная учеником, помечается `added_by=student` и ждёт подтверждения — данные от ученика не приравниваются к проверенным
2026-08-22 — ученик снимает только то, что добавил сам — решение директора отменяет тот, кто его принял
2026-08-22 — ответ квиза сразу ложится в профиль, но строка остаётся неподтверждённой — иначе ученик заполнил анкету, а кабинет остался пустым; при этом слова ученика не должны выглядеть проверенным фактом
2026-08-22 — источник `student_onboarding` добавлен в реестр рядом с manual/import/ai/sync — по журналу всегда видно, что число назвал ученик, а не сотрудник
2026-08-22 — прогресс квиза хранится по шагам в `OnboardingAnswer` — ученик выходит на третьем вопросе и возвращается через неделю, отвечать заново он не должен
2026-08-22 — `award()` принимает только виды из `XPKind`, и в перечне нет ни одного пункта про баллы — инвариант №12 держится кодом, а тест проверяет сам перечень на слова вроде «ielts» и «балл»
2026-08-22 — одно начисление на объект (уникальность по `student+kind+object`) — пере-открыл задачу и закрыл снова это не второй повод дать XP
2026-08-22 — стрик пересчитывается и при чтении, а не только при начислении — иначе у ушедшего на каникулы он висел бы вечно
